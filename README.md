# `@nuxthub/db/schema` drags `postgres` into the client bundle → `nuxt build` fails

Minimal reproduction for **[nuxt-hub/core](https://github.com/nuxt-hub/core)**.

`nuxt build` fails because the generated **`@nuxthub/db/schema`** entry — the one NuxtHub
documents as the *client-safe* way to share the DB schema with the Vue app — pulls the
`postgres` driver into the **client/browser** bundle:

```
✗ Build failed
RollupError: postgres/src/connection.js (5:9): "performance" is not exported by
"__vite-browser-external", imported by postgres/src/connection.js
  5: import { performance } from 'perf_hooks'
```

## Reproduce

```bash
pnpm install
pnpm build      # or: ./node_modules/.bin/nuxt build
```

## Setup (all this repo contains)

- `nuxt.config.ts` — enables NuxtHub's Drizzle DB with the **`postgres-js`** driver (the
  production driver, e.g. Cloudflare Hyperdrive). No DB connection is needed to reproduce.
- `server/db/schema/users.ts` — a normal Drizzle table.
- `server/db/schema/todos.ts` — a table that references `users` via
  `import { schema } from '@nuxthub/db'` (the idiomatic way to reference NuxtHub's
  aggregated tables — and the **only** way to reach tables you don't author yourself, e.g.
  the `user` table generated by `@onmax/nuxt-better-auth`).
- `app/app.vue` — **client** code that value-imports a table from `@nuxthub/db/schema` and
  derives a Zod schema with `drizzle-zod` (`createInsertSchema`). This is the documented
  "Sharing schema with Vue" use case and the reason to import schema on the client at all.

## Root cause — why this is a NuxtHub issue, not user error

1. NuxtHub generates the `@nuxthub/db` package with two entries:
   - `@nuxthub/db` (`.` → `db.mjs`) → exports the **`db` postgres client** + `schema`.
   - `@nuxthub/db/schema` (`./schema` → `schema.mjs`) → the table defs, **documented as
     client-safe**.
2. The generated **`package.json` has no `"sideEffects": false`**, and `postgres` is not
   side-effect-free either. So even when the `postgres` import is **dead code**, Rollup/Vite
   cannot tree-shake it out of a consumer (client) bundle.
3. When any `server/db/schema/**` file imports `@nuxthub/db` (the `.` entry — the normal way
   to cross-reference aggregated tables), NuxtHub **inlines `db.mjs` (postgres client) into
   the `@nuxthub/db/schema` bundle**. The "client-safe" entry now contains
   `import postgres from "postgres"` + bare top-level `new Proxy(...)` statements that no
   bundler will drop. → `postgres` → `perf_hooks`/`net`/`tls` → client build fails.

Inspect the generated output after `pnpm install`:

```bash
head -2 node_modules/@nuxthub/db/schema.mjs   # import { drizzle } from "drizzle-orm/postgres-js"; import postgres from "postgres";
cat  node_modules/@nuxthub/db/package.json    # no "sideEffects": false
```

### Boundary (confirms the cause)

| `server/db/schema/todos.ts` imports        | `schema.mjs` contains postgres | `nuxt build` |
| ------------------------------------------ | ------------------------------ | ------------ |
| `import { schema } from '@nuxthub/db'`     | yes                            | ❌ fails      |
| `import * as schema from '@nuxthub/db/schema'` | no                         | ✅ passes     |

The second row is a **workaround**, not a fix: `@nuxthub/db` is the idiomatic / only way to
reference auto-generated tables, and dead db-client code should never be able to break a
client build in the first place.

## Suggested fix (in `@nuxthub/core`)

- Emit **`"sideEffects": false`** in the generated `@nuxthub/db/package.json`
  (`src/db/setup.ts`), so the dead `postgres` import is tree-shakeable.
- Keep the **`@nuxthub/db/schema` bundle genuinely postgres-free** — don't inline `db.mjs`
  (the db client) into it (`src/db/lib/build.ts`); externalize / tree-shake
  `postgres` + `drizzle-orm/postgres-js` from the schema entry.

## Expected

Importing the DB schema from `@nuxthub/db/schema` into client code (to derive validation with
`drizzle-zod`, share types, etc.) must **not** pull the `postgres` driver into the browser
bundle, and `nuxt build` should succeed.
